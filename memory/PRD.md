# Brazil Lacrosse Athlete Monitoring System - PRD

## Product Overview
Two connected apps for athlete monitoring and workload management for Brazil Lacrosse National Teams (Men and Women).

## Core Features

### 1. Authentication & User Management
- **Status**: ✅ Complete
- JWT-based authentication with role-based access (Athlete, Staff, Admin)
- Self-registration for athletes with admin approval workflow
- **Staff Registration**: Staff can register with Coach/Physio/Research roles
- **Admin Definition**: Single predefined admin (pataradaniel@gmail.com)
- **Change Password**: ✅ NEW - Added 2026-11-01 — card on Profile Settings (athletes and staff); `PUT /api/auth/change-password` requires login + current password, new password ≥ 8 chars and different from the current one

- **Athletes**: Can log daily data, view own history
- **Staff (Coach/Physio/Research)**: Dashboard access, view all athlete data
- **Admin**: Full access including approve/reject athletes, manage users

- **2026-09-10**: **The Fittest — correção do bug de fuso horário (treino não aparecia para postar) + fuso por atleta**. Causa raiz: os treinos eram salvos em UTC, mas a elegibilidade do The Fittest comparava com a data LOCAL (Filadélfia) via regex de texto (`^YYYY-MM-DD`) — treinos à noite "viravam o dia" em UTC e nunca casavam com o "hoje", bloqueando a opção de postar. Correção (escopo restrito ao The Fittest, zero impacto nos dashboards ancorados no horário Leste): (1) novos helpers `_resolve_tz`/`_today_in_tz`/`_local_date_of` em `the_fittest_routes.py` que convertem timestamps (aware→tz; naive→tratado como local) para a data local no fuso do atleta; (2) `GET /api/fittest/eligibility` e `GET /api/fittest/my-trainings-today` agora aceitam `?tz=` (IANA); `create_post` recebe `tz` no corpo; (3) `_recovery_day_points`/`_has_recovery_log_today` passam a casar recovery pelo `created_at` (UTC confiável) convertido ao fuso do atleta — recovery também segue o fuso de cada atleta; (4) `my-trainings-today` exibe o horário da sessão já convertido ao fuso local. Frontend: `TheFittest.js` envia `DEVICE_TZ = Intl.DateTimeFormat().resolvedOptions().timeZone` nas 3 chamadas; `PostTrainingLog.js` passa a mostrar o horário local atual como padrão e a salvar o wall-clock local do atleta (naive) em vez de converter para UTC. Verificado por curl em 2 fusos (America/New_York noite + America/Sao_Paulo) e fluxo completo (foto+post = +1), e 100% pelo testing agent (iteration_31): logar treino → aparecer elegível no compositor → publicar +1; gate de recovery preservado.
